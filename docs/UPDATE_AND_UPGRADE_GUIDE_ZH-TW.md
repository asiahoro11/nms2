# NMS 更新與升級操作手冊

本手冊適用於 Windows、Linux AMD64 與 Linux ARM64 正式版本。更新前請先確認新版本架構與主機一致，並使用發布隨附的 SHA-256 清單驗證檔案。

## 一、升級原則

- 升級時只移轉執行資料，不要把舊版程式、前端檔案或工具覆蓋到新版目錄。
- 必須保留的主要資料為 `data` 目錄；若安裝目錄根層另有 `config.yaml`，也要一併保留。
- 不要從其他版本目錄啟動新版程式。NMS 會依目前工作目錄讀取 `./data/nms.db`，從錯誤目錄啟動就可能看見空白或舊資料庫。
- 第一次啟動新版時會自動執行資料庫結構升級。執行期間不得中斷電源、強制關閉程式或同時啟動舊版。
- 升級後若需要回復舊版，必須同時還原升級前的資料庫備份；不要讓舊版直接使用已升級的資料庫。

## 二、升級前檢查

1. 確認目前版本、目標版本與作業系統架構。
2. 閱讀目標版本的 `RELEASE_NOTE.txt` 與 `RELEASE_NOTES.md`。
3. 確認磁碟空間足以存放：目前系統、完整備份、新版解壓縮目錄及操作日誌。
4. 記錄目前 NMS 安裝目錄、啟動方式、服務帳號、監聽 IP／Port 與防火牆設定。
5. 若從舊式對稱 License 版本升級至 Ed25519 License 版本，先向授權窗口取得新版授權或完成受控遷移；不要把簽發私鑰放到 NMS 主機。
6. 若已啟用執行檔完整性驗證，確認新版雜湊已依維護程序更新，避免新版第一次啟動即進入鎖定狀態。

## 三、建立完整備份

### 建議方式

先在 NMS 管理介面匯出加密系統備份，將備份檔保存到另一個磁碟或受控備份位置。確認檔案大小合理，並記錄備份密碼與 SHA-256；密碼不要和備份檔放在同一位置。

### 停機後檔案備份

1. 完整停止 NMS 主程式或服務。
2. 確認沒有 `nms_server` 程序仍在執行。
3. 將整個 `data` 目錄複製到有日期與版本名稱的備份目錄。
4. 若根目錄存在 `config.yaml`，一併備份。
5. 特別確認下列項目已包含在備份中：
   - `data/nms.db`
   - `data/nms.db-wal`、`data/nms.db-shm`（存在時）
   - `data/uploads`
   - JWT、加密或其他執行期金鑰檔案
   - 系統設定、License 與設備資料

> 不要只複製 `nms.db` 而遺漏仍存在的 WAL/SHM，也不要在 NMS 執行中直接複製 SQLite 檔案。

## 四、Windows 升級步驟

1. 停止 NMS，並在工作管理員或 PowerShell 確認 `nms_server.exe` 已結束。
2. 完成上一節的完整備份。
3. 將新版 ZIP 解壓縮到新的空白目錄，例如 `C:\NMS\v1.2.4.11`。不要直接解壓縮覆蓋舊版目錄。
4. 以發布的 `RELEASE_SHA256` 或交付雜湊核對新版 ZIP。
5. 從舊版目錄複製整個 `data` 目錄到新版根目錄，取代新版的空白 `data` 目錄。
6. 若舊版根目錄存在 `config.yaml`，複製到新版根目錄；若設定檔位於 `data/config.yaml`，則已隨 `data` 移轉。
7. 不要複製舊版的 `nms_server.exe`、`bin`、`tools`、HTML、JavaScript 或其他程式檔到新版。
8. 從新版根目錄執行 `start_nms.bat` 或 `start_nms.ps1`，不要從命令提示字元的其他目錄直接執行 EXE。
9. 等待資料庫遷移與服務啟動完成，再進行驗證。

## 五、Linux 升級步驟

1. 停止 systemd 服務或目前執行中的 NMS 程序，確認沒有舊程序占用資料庫與連接埠。
2. 完成完整備份。
3. 將符合主機架構的新版壓縮檔解壓縮到新的空白目錄，例如 `/opt/nms/v1.2.4.11`。
4. 使用 `sha256sum` 核對發布檔案。
5. 將舊版的整個 `data` 目錄複製到新版根目錄；有根層 `config.yaml` 時也一併複製。
6. 保留原本服務帳號的檔案擁有者與最小必要權限，不要將資料庫設為所有人可寫。
7. 不要將舊版執行檔、`bin`、`tools` 或靜態前端檔案覆蓋到新版。
8. 切換到新版根目錄後執行 `./start_nms.sh`，或將 systemd 的 `WorkingDirectory` 與 `ExecStart` 更新到新版目錄後啟動服務。
9. 確認服務穩定後，再更新正式版目錄的捷徑或符號連結。

## 六、升級後驗證

依序檢查：

1. 系統顯示的版本號為目標版本。
2. 登入、角色權限與 TOTP 正常。
3. SuperAdmin 不出現在一般登入與使用者清單；隱藏入口與權限限制正常。
4. License 狀態、授權模組與設備數量正確。
5. 設備、拓樸、告警、報表、IoT、PDU、攝影機與門禁資料均存在。
6. SNMP、Ping、Modbus TCP、RS485、MQTT、SSH、RTSP 等實際輪詢正常。
7. IoT 離線佇列與拋轉目標沒有遺失，毫秒週期設定正確。
8. 公司 Logo、上傳檔案、郵件、Webhook、Syslog 與排程設定正常。
9. 檢查 `server.log`，確認沒有 migration、database locked、integrity lockdown 或 License 驗證錯誤。
10. 建立一份升級後加密備份並保存。

建議至少觀察一個完整輪詢與拋轉週期，再結束維護時段。

## 七、避免讀取到舊資料庫

若新版顯示舊資料或空白資料，先停止 NMS，再檢查：

1. 實際執行的 `nms_server` 路徑是否為新版目錄。
2. 啟動時的工作目錄是否為新版根目錄。
3. 新版根目錄的 `data/nms.db` 是否為本次移轉的資料庫。
4. 是否仍有舊版程序或 Windows 服務正在執行。
5. Windows 服務或 Linux systemd 是否仍指向舊版 `WorkingDirectory`／執行檔。
6. 桌面捷徑是否仍連到舊版目錄。

確認前不要刪除任何資料庫。先比對路徑、檔案大小、修改時間與備份雜湊。

## 八、SuperAdmin 一次性工具

新版發布包可能包含 `manage_superadmin.bat` 與 `tools/superadmin-local.exe`，供首次本機設定或經授權的密碼復原使用。

- 已完成 SuperAdmin 設定且驗證登入成功時，不必在每次升級重新執行工具。
- 升級後確認 SuperAdmin 正常，再依《Windows SuperAdmin 一次性設定手冊》刪除上述兩個工具檔案。
- 若日後需要本機復原，從原始且已驗證 SHA-256 的發布包重新取得，不要保存散落副本。

## 九、回復舊版

只有在新版無法於維護時間內排除問題時才執行回復：

1. 停止新版 NMS，確認程序已完全結束。
2. 保存新版的日誌與故障資訊，供後續分析。
3. 將新版目錄保留，不要覆蓋或刪除。
4. 恢復升級前的舊版程式目錄。
5. 使用升級前建立的完整備份還原舊版 `data` 與根層 `config.yaml`。
6. 啟動舊版並重新執行核心功能驗證。

> 不支援只更換回舊執行檔、卻沿用已由新版遷移過的資料庫。這可能造成資料表或設定不相容。

## 十、完成與留存

升級完成後記錄：舊版與新版版本號、升級時間、操作者、備份位置與 SHA-256、發布包 SHA-256、資料庫遷移結果、驗證結果、異常與處置。確認回復窗口結束後，再依公司保存政策清理舊版程式與備份；不要直接刪除仍在保存期限內的資料。
